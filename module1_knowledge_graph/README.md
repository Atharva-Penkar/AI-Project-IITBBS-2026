# Knowledge graph and diagnostic search

This folder holds the course content and the search code that works on it. It answers two questions: what depends on what, and when a student is stuck on a concept, which earlier concept is the likely cause?

The course is a unit on search algorithms with 11 concepts (AI problem solving, graph basics, BFS, DFS, path cost, queues and priority queues, heuristics, UCS, greedy search, admissibility, A*), 17 prerequisite links, 22 misconceptions and 23 learning resources. The same catalog is loaded by the student model, planner, scheduler and `main.py`.

## What's in it

| File | Purpose |
|---|---|
| `knowledge_graph.json` | The course data, and the source of truth. Everything else is generated from or reads this |
| `concepts.csv`, `prerequisite_edges.csv`, `misconceptions.csv`, `misconception_paraphrases.csv`, `learning_resources.csv` | The same data as tables, generated by `export_csv.py` |
| `resource_links.json` | Web links for each concept |
| `knowledge_graph.png` | A picture of the graph, generated by `draw_graph.py` |
| `search.py` | BFS and DFS over prerequisites, study plans, and a general weighted search that does A*, greedy best-first and uniform-cost search |
| `knowledge_graph.py` | Loads the graph and provides `diagnose` and `explain` |
| `student_graph.py` | Puts one student's estimates on top of the graph: concept status, study plan, per-student diagnosis |
| `catalog.py` | Converts the graph into the shared `CourseCatalog` that other modules use |
| `astar_examples.py` | A four-node graph where A* has a known optimal answer, used to test the diagnosis |
| `demo.py` | A guided tour of the above |

## Running it

From the project folder (see the main README for setup):

```bash
python -m module1_knowledge_graph.demo
python -m pytest module1_knowledge_graph
```

If you edit `knowledge_graph.json`, regenerate the tables and the picture:

```bash
python -m module1_knowledge_graph.export_csv
python -m module1_knowledge_graph.draw_graph
```

A test checks that the CSV files match the JSON, so forgetting the first command shows up as a failing test.

## Diagnosing a difficulty

```python
from module1_knowledge_graph.knowledge_graph import diagnose, explain

result = diagnose("Astar", "I thought A* only uses the heuristic h(n), not path cost.")
print(explain(result))
```

`diagnose` looks at the target concept and everything it depends on. Each candidate gets a score:

- `4 * (1 - mastery)` if a mastery estimate is supplied for it.
- `5 * match` if the student's own words match one of its stored misconceptions. A match means the text contains at least half of the misconception's keywords and shares at least two words with it. Each misconception is also stored with two alternative wordings, so students don't have to repeat our sentence. Notation such as `h(n)` and "path cost" is mapped to words first.

Candidates are returned best first, with their examples, exercises, notes and links, plus a suggested next step. Concepts with no evidence are still listed, marked `unverified`, so a teacher knows which ones to check with a quick question.

One refinement: if all the words that matched one concept's misconception were also matched, more strongly, on another concept, the weaker match isn't counted as separate evidence. Without this, "an overestimating heuristic still guarantees an optimal A* path" would produce a false second cause on A* itself. Two genuinely different misconceptions in one answer are both kept.

## Using a student's estimates

`student_graph.py` doesn't keep its own mastery numbers. It reads the estimates produced by `module3_student_model`.

```python
from module1_knowledge_graph.catalog import load_course_catalog
from module1_knowledge_graph.student_graph import concept_status, diagnose_student, study_plan
from module3_student_model import StudentModelEngine
from shared.schema import Event, EventType

catalog = load_course_catalog()
engine = StudentModelEngine(catalog)
for _ in range(3):
    engine.update(Event(student_id="s1", concept_id="Path_Cost", type=EventType.QUIZ_ANSWER,
                        correct=False, chosen_misconception="g_is_remaining_cost"))

student = engine.get_student("s1")
print(concept_status(student, "Path_Cost"))     # misconception
print(study_plan(student, "Astar"))             # unmastered prerequisites, foundations first
print(diagnose_student(student, "Astar")["next_step"])
```

A concept's status is one of `unknown` (no evidence yet), `not_learned` (the student is struggling but shows no known misconception), `misconception` (a stored misconception is likely held) or `mastered` (mastery at or above 0.9).

## Testing against A* failures

`astar_examples.py` reproduces three typical student errors on a four-node graph where the optimal path costs 4, and checks that each is traced to the right concept.

| Student error | What it does to A* | Cost found | Diagnosed concept |
|---|---|---|---|
| Uses only h(n) | Behaves as greedy search | 6 | A* Search |
| Thinks a priority queue is first-in-first-out | FIFO frontier | 6 | Queues and Priority Queues |
| Thinks an overestimating heuristic is fine | Heuristic overestimates | 6 | Admissible and Consistent Heuristics |

## Limitations

- The misconceptions and their alternative wordings are our own drafts. An instructor hasn't reviewed them, and two wordings per misconception won't cover everything students say.
- The links in `resource_links.json` came from web searches. We haven't checked each one, so open them before giving them to students.
- Diagnosis is word matching, not understanding. "A* uses only g(n)" and "A* uses only h(n)" are hard to tell apart when a student mentions both.
